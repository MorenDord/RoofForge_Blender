# RoofForge 0.3.21 — установка и тестирование

Экспериментальная сборка для Blender 5.0+. Растерный PNG-превью полностью удалён. Остаётся только прямой GPU-векторный план в основной вкладке **RoofForge** N-панели.

## Что изменилось

- Линии рисуются сглаженным GPU polyline-шейдером Blender, без PNG и без фоновой генерации изображения.
- Номера скатов соответствуют нумерации Pitch (01, 02, 03…). Положение считается по площадному центроиду всей области соответствующего Pitch, а не по крупнейшей отдельной грани.
- Превью находится в сворачиваемой секции **Roof Plan** внутри основной панели RoofForge, сразу под кнопкой Create / Update Roof. Pitch и общие параметры находятся ниже этой секции в той же панели.
- GPU-превью центрируется по области содержимого активной вкладки N-панели: расчёт исключает левую полосу категорий Blender. Ширина полосы учитывает обычный/компактный режим вкладок и масштаб View2D. Пустая полноширинная строка резервирует только высоту, а Scissor ограничивает GPU-слой рассчитанным квадратом.
- Размер и координаты схемы рассчитываются через оценку `U.widget_unit` и фактическую ширину активной вкладки. Bounding box вписывается по большей стороне с отступом 7,5%.
- При слишком узкой N-панели схема скрывается, вместо того чтобы вылезать поверх соседнего редактора.
- Цвет линий и цифр подбирается по яркости темы интерфейса Blender.
- Опция **Debug UI bounds** рисует границы UI-региона (красная), расчётного слота (жёлтая) и локального GPU viewport (голубая). Преобразования View2D выводятся текстом через публичные методы API.
- Если крыша ещё не создавалась, в панели доступны Initial Pitch, Thickness, Overhang, Converge corners и Live Update.
- Initial Pitch задаёт общий угол для всех рёбер при первом создании крыши. После создания индивидуальные Pitch можно менять независимо. У каждого Pitch есть стрелки влево и вправо. Они строят опорную поверхность без выбранного ската, находят реальные вершины, сформированные остальными скатами, вычисляют точный угол пересечения с ближайшей такой вершиной и проверяют, что в полной крыше появилась общая вершина. Если подходящая вершина недостижима в этом направлении, угол не меняется, а причина отображается под списком Pitch.

## Ограничения генерации в 0.3.16

- Вогнутый XY-контур с разными высотами вершин временно не поддерживается. При попытке Create / Update Roof аддон выдаёт предупреждение и не запускает построение поверхности. Если крыша уже существует, неудачная попытка обновления не заменяет её.
- Для вогнутых контуров используй одинаковую высоту всех вершин карниза. Выпуклые контуры с разными высотами остаются поддержанными.
- Экспериментальный модуль смешанно-высотной вогнутой огибающей не включается в устанавливаемый ZIP.

## Центровка и геометрическое притягивание Pitch (0.3.21)

- Горизонтальный центр считается по области содержимого вкладки RoofForge, а не по всему UI-региону вместе с вертикальными вкладками категорий.
- Учитывается ширина category rail: 1.0 `U.widget_unit` для обычных вкладок и 1.4 для компактных. Поправка масштабируется через публичное преобразование View2D.
- В режиме Debug UI bounds зелёная вертикаль и расчётный GPU canvas должны совпадать с серединой области содержимого; диагностический текст показывает `RoofForge tab content bounds X` и `RoofForge tab content midpoint X`.
- Ряд индивидуального угла занимает всю доступную ширину: номер ската, стрелка предыдущего события, ползунок угла и стрелка следующего события.
- Кнопки Pitch больше не ориентируются на изменение количества вершин. Опорные точки берутся из поверхности, построенной без редактируемого ската; учитываются только внутренние вершины, где сходятся как минимум два других ската.
- Угол для каждой такой точки решается аналитически из уравнения плоскости ската. Проверочная сборка обязана подтвердить одну общую 3D-вершину выбранного ската и соседних плоскостей.
- Влево выполняется поиск меньшего угла, вправо — большего. Выбирается ближайшее подтверждённое событие в заданном направлении. Неудачная попытка больше не скрывается: в панели появляется диагностическое сообщение.

## Установка

1. Удали предыдущую тестовую версию RoofForge в **Edit → Preferences → Get Extensions**.
2. Открой Actions: https://github.com/MorenDord/RoofForge_Blender/actions
3. Выбери последний успешный workflow **RoofForge tests** на ветке `feature/0.2.0-arbitrary-contours-live-pitch`.
4. Скачай внешний архив `roof_forge-0.3.21-blender-5.0.1` и распакуй его один раз.
5. Установи внутренний `roof_forge-0.3.21.zip` через **Preferences → Get Extensions → Install from Disk…**. Внутренний ZIP не распаковывай.
6. Внизу панели RoofForge должна появиться строка **Geometry core: Rust (5/5 kernels)**. Если отображается Python fallback, native wheel не загрузился.

## Проверка перед созданием

1. Выдели Mesh-контур и открой вкладку **RoofForge** в N-панели.
2. До создания крыши должны быть видны Initial Pitch, Thickness, Overhang, Converge corners и Live Update.
3. Установи, например, Initial Pitch = 42°. Нажми Create / Update Roof.
4. Проверь, что все первоначальные Pitch-поля получили 42°. После создания измени один Pitch — изменение Initial Pitch не должно переписывать уже заданные индивидуальные углы.

## Проверка геометрического притягивания Pitch

1. Создай прямоугольный контур 4 × 3 и создай крышу с Pitch = 20°.
2. Для скатов 02, 03 и 04 установи 30°, оставив скат 01 на 20°, затем нажми Create / Update Roof.
3. Нажми стрелку вправо у Pitch 01. Угол должен измениться примерно на 49,11°: плоскость первого ската пройдёт через вершину, сформированную тремя остальными скатами.
4. Нажми Create / Update Roof и проверь в Roof Plan, что в точке (2, 1) находится одна общая вершина нескольких скатов.
5. Проверь стрелку влево на другом профиле. Если подходящего узла в указанном направлении нет, Pitch не должен изменяться; под списком появится сообщение об отсутствии вершины.

## Проверка векторного превью

1. После создания крыши открой секцию **Roof Plan** в той же вкладке RoofForge и оставь включённым Show preview.
2. Проверь сглаживание линий на диагоналях и в местах соединения скатов.
3. Поменяй Pitch несколько раз. Номера должны двигаться плавно и оставаться в центре своих областей; не должно быть скачков между соседними гранями.
4. Проверь асимметричный и L/U-контур: bounding box должен быть отцентрирован относительно области превью.
5. Сильно сузь N-панель. Схема должна скрыться, не заходя на соседний редактор. Расширяй панель — квадрат превью и сама схема должны увеличиваться так же, как прежняя растровая миниатюра; контур должен оставаться по центру квадрата.
6. Проверь тёмную и светлую темы Blender: линии и номера должны сохранять контраст.
7. Прокрути N-панель вниз: GPU-план должен исчезнуть из области просмотра, если секция Roof Plan свернута или не видна при прокрутке; Pitch и остальные параметры должны оставаться доступными ниже. Проверь, что линии и номера не перекрывают ни одну строку Pitch.

## Диагностика смещения превью

1. В секции Roof Plan включи **Debug UI bounds**.
2. Нажми **Copy debug text**. Полный снимок диагностики скопируется в буфер обмена обычным текстом.
3. Вставь скопированный текст прямо в сообщение. Скриншот не нужен.
4. В диагностике есть координаты Region и GPU viewport, оценка UI unit и размера template_icon, расчётный слот и преобразование координат View2D через публичные методы `region_to_view()` / `view_to_region()`.

Диагностический режим нужен только для замера. Он выключен по умолчанию и не влияет на геометрию крыши.

## Остальные проверки

- Измени Number size и Line thickness; GPU-схема должна перерисовываться без PNG-файлов и таймеров.
- Проверь несколько окон 3D Viewport, изменение масштаба UI и отключение/повторное включение аддона.
- Убедись, что после удаления крыши Create / Update пересоздаёт её, а после Edit Mode правок исходного контура пересобирает геометрию.

## Положительный свес на вогнутых контурах (0.3.8)

Для плоских по Z вогнутых контуров L/U теперь доступен положительный свес. Включи **Converge corners** (опция включена по умолчанию): смежные полосы свеса сходятся в общей угловой точке, а каждая полоса остаётся на плоскости своего исходного ската. Поддерживающая линия исходного карниза не перемещается.

Проверка: создай L- или U-контур, задай положительный Overhang (например, 15 см) и нажми Create / Update Roof. Попробуй изменить Pitch одного из рёбер — Live Update должен перестроить крышу вместе со свесом.

Ограничения этой версии: все вершины исходного вогнутого карниза должны иметь одну высоту Z; свес должен оставлять внешний контур простым и охватывать исходный контур. Слишком широкий свес, закрывающий узкий проём L/U, будет отклонён с диагностикой — уменьши его. Включённый **Converge corners** обязателен для вогнутого контура. Поддержка не означает, что любой произвольный вогнутый многоугольник пройдёт weighted-wavefront: неразрешимые или неоднозначные события генератора по-прежнему отклоняются, а предыдущая корректная крыша сохраняется.


## Геометрическая проверка самопересечений (0.3.9)

Перед созданием Blender Mesh RoofForge проверяет не только замкнутость и manifold-топологию оболочки, но и пересечения между несмежными треугольными участками поверхности. Пары сначала отбираются по пространственным AABB, затем выполняется точная проверка треугольников, включая копланарный случай.

Если две несмежные грани пересекаются, генерация прекращается с диагностикой вида **«Грани 4 и 7 геометрически пересекаются»**. Исходный объект и последняя корректная крыша не заменяются. Обычные общие рёбра и вершины соседних граней не считаются самопересечением.

Это дополнительная защита, а не доказательство корректности любой произвольной оболочки: проверка сравнивает несмежные грани и не считает ожидаемое касание через общие индексы вершин самопересечением.


## Чистая геометрия без лишних луп-катов (0.3.10)

После построения RoofForge объединяет соседние грани, лежащие в одной плоскости, и удаляет промежуточные вершины, которые после объединения соединяют только два ребра. Полностью свободные вершины тоже удаляются. Это сокращает сетку до крупных N-gon/quad/triangle областей там, где линии не меняют форму или топологию. Настоящие рёбра перелома скатов, рёбра гребней/ендов и углы силуэта сохраняются.

В CI есть отдельный тест: искусственно разрезанный на мелкие плоские грани прямоугольный параллелепипед должен после очистки стать сеткой из 8 вершин, 12 рёбер и 6 квадов. На сгенерированной крыше проверяется отсутствие свободных и двухрёберных вершин, а также внутренних копланарных рёбер.


## Практически копланарные швы (0.3.11)

В 0.3.10 удалялись только строго копланарные внутренние рёбра. Теперь очистка повторяется до стабилизации сетки и дополнительно схлопывает очень близкие к плоскости полосы: угол между соседними гранями не более 0,05°, отклонение от общей плоскости не более 10 миллионных от габарита сетки. Это устраняет тонкие остаточные полосы, вызванные численной погрешностью построителя.

Выраженный перелом скатов сохраняется. В Blender smoke-тесте узкая грань с наклоном 0,04° должна схлопнуться, а настоящее ребро с углом 5° должно остаться. Это не режим автоматического упрощения произвольных малых скатов.


## Вогнутый контур с разными высотами карниза (0.3.12)

Для вогнутого XY-контура с разными высотами вершин точная плоскостная огибающая строится первой. Если она создаёт внутренний разрыв (например, **«Верхняя поверхность разорвана»**), RoofForge автоматически использует непрерывное поле конечных сегментов:

- На внутренних участках рёбер поверхность остаётся на исходных плоскостях скатов.
- Вокруг концов рёбер используются радиальные переходные участки, чтобы высота не прыгала на внутренних линиях.
- Эти переходные зоны адаптивно триангулируются с допуском 0,1% габарита сетки и максимальной глубиной 4. Копланарные грани по-прежнему объединяются; треугольники в зоне реального перехода сохраняются.

Проверка: используй вогнутый L-контур с разной высотой вершин и нажми Create / Update Roof. Поверхность должна покрывать исходный контур, а оболочка — проходить проверку manifold и самопересечений. Если сегментное поле занижает заданную границу или не проходит проверку, RoofForge остановит генерацию с диагностикой, а не выдаст открытую сетку.

Ограничение: положительный свес для вогнутого контура с разными высотами карниза всё ещё не поддерживается.


## Native Rust core в Blender 0.3.21

В установочный ZIP теперь включены stable-ABI wheels для Linux x64, Windows x64, macOS x64 и macOS ARM64. Blender устанавливает совместимый wheel в собственный `site-packages` расширения; сетевое скачивание ядра при запуске не требуется.

Проверка после установки:
- Внизу N-панели RoofForge ожидается **Geometry core: Rust (5/5 kernels)**.
- В консоли Blender доступны сообщения о Rust backend и полном наборе ядер.
- Если wheel отсутствует или не подходит платформе, RoofForge продолжает работать через Python fallback.
- Ручной GUI тест интерфейса нужен дополнительно к автоматическому background smoke; автоматический тест подтверждает загрузку wheel, работу 64-рёберного контура и создание реального Blender Mesh datablock.
