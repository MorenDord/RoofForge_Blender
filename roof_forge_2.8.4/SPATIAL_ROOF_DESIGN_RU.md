# RoofForge 2.9.0 — пространственная геометрия, волновой фронт и узлы профилей

## 1. Входной контур и углы

Карниз — упорядоченный замкнутый loop из XYZ-вершин. Каждому ребру соответствует один угол ската, хранящийся в радианах. Индексы параметров spatial_pitch_01...32 идут по порядку обхода исходного loop и сохраняются при смене направления обхода.

Контур проверяется на нулевые рёбра, нулевую XY-площадь и другие условия, необходимые для однозначной топологии. В UI оставлен единственный режим — HIP_FREE («Вальмовая / свободные углы»); selector типа крыши скрыт.

## 2. Получение топологии скатов

Пути построения различаются по геометрии карниза:

- Плоский контур с единым углом использует проверенный straight-skeleton.
- Плоский контур с индивидуальными углами использует взвешенный волновой фронт. Для каждого ребра рассчитывается inward speed из фактического угла и продольного уклона ребра; solver пересчитывает collapse- и split-события, а не переносит готовый равномерный скелет.
- Неплоский контур с единым углом использует reflex-aware topology template с последующим переносом вершин на 3D support planes.
- Неплоский контур с разными углами получает event topology от weighted wavefront на плоском proxy с теми же per-edge скоростями; затем исходные грани поднимаются на соответствующие 3D support planes.

Каждое ребро карниза задаёт опорную плоскость, проходящую через его реальные XYZ-концы. Угол определяет подъём поверхности внутрь XY-проекции. После подъёма выполняются ограниченная коррекция событийных узлов, схлопывание допустимых микроскопических sliver-рёбер и строгая проверка результата.

### Важное ограничение модели

Для неплоских контуров это topology-template + support-plane lifting, а не общий аналитический 3D wavefront, способный пересчитать любой пространственный split/collapse независимо от проекции. Поэтому при больших различиях углов или высот порядок событий может измениться так, что исходная топология уже не подходит. В этом случае генерация должна завершиться SpatialRoofError, а не ослаблять проверку замыкания.

Проверенные регрессионные области включают:
- плоские L-/U-планы с разными углами;
- неплоские L-/U-планы с диапазоном высот карниза примерно 0.20–0.24 м;
- те же вогнутые планы с изменяемыми per-edge pitch в районе 32–38°;
- косоугольный многорефлексный контур;
- крестообразный 12-рёберный план с четырьмя reflex-углами и пространственными высотами.

Геометрия валидируется независимо от того, прошёл ли отдельный экспериментальный weighted solver probe. Два прямых теста экспериментального модуля на неплоском L-контуре остаются известными отказами; production path для неплоских равномерных скатов использует lifting path, а не этот experimental call.

## 3. Валидация поверхности

После embedding проверяются:
- покрытие каждого исходного ребра карниза нижней границей крыши;
- связность фасет и кратность использования рёбер;
- сохранность соответствия source-edge ID;
- отсутствие микроскопических sliver-граней после безопасной локальной коррекции;
- геометрические самопересечения и невозможные/неплоские узлы.

Переходные грани в многолучевых узлах имеют отдельный source ID и не классифицируются как дополнительные коньки или ендовы. Точки, которые нельзя согласовать в пределах допустимой коррекции, не сливаются произвольно.

## 4. Свес

Свес строится из исходной верхней поверхности до добавления переходных граней и толщины. Каждое граничное ребро смещается в плоскости своей фасеты, перпендикулярно 3D-кромке. Поэтому пространственный свес — длина по поверхности ската, а не только XY-вынос.

Сопряжение соседних полос выполняется отдельной угловой переходной геометрией. После расширения создаётся mesh-экструзия толщины. Исходная surface mesh сохраняется как скрытый mesh datablock с fake user, чтобы повторные команды профилей после reopen .blend анализировали ту же поверхность.

## 5. Коньки и ендовы

Классификатор работает по готовому mesh: соседние грани образуют единый граф стыков, а выпуклость/вогнутость определяется по нормалям и ориентации ребра. Профильные команды не запускают solver крыши.

Для каждого seam edge создаются две inset-полосы в локальных плоскостях смежных граней. Для обычных узлов используются общие miter-сечения. Для узлов с несколькими ветвями центр разделяется на локальные сечения, затем стыкуется общей переходной поверхностью, упорядоченной по угловым секторам смежных roof faces. Контур переходной поверхности проверяется на вырождение и самопересечение до триангуляции. Финальная профильная оболочка должна быть замкнутой manifold-сеткой.

Команды «Создать на выбранной крыше» и «Обновить» анализируют существующий объект; глобальная плоскостность всего Mesh не требуется. Плоскость каждой грани оценивается отдельно. Небольшая локальная неплоскостность допускается в пределах face-fit tolerance; gross warp отклоняется. Никакой невалидный quad не превращается молча в сильно искривлённую грань: inset-полосы при необходимости триангулируются.

## 6. Фальцевая раскладка

Фальцы идут от карниза к коньку по направлению максимального спуска соответствующего ската. Ширина и шаг измеряются по поверхности фасеты. Основание заглубляется относительно верхней поверхности на долю толщины крыши; высота ограничена 90% высоты конька. Продольные боковые кромки фальцев помечаются Seam.

Изменение параметров фальцев перестраивает только mesh фальцев, не запускает solver крыши. Для пространственных скатов используются сохранённые source faces и их локальные плоскости.

## 7. Предпросмотр в панели

_spatial_preview_png строит верхний вид по фактическим фасетам результата build_spatial_roof_mesh, то есть индивидуальные углы влияют на контуры скатов. Рендер идёт в RGBA с прозрачным фоном; белые линии рисуются на 4x supersampled bitmap и уменьшаются с alpha coverage. Для каждого ската выбирается точка с наибольшим расстоянием до его контура. Размер цифры подгоняется по локальному clearance; если номер не помещается безопасно, он не рисуется поверх соседней грани. UI масштабирует картинку по ширине панели.

## 8. Проверки и runtime

Обязательные CI-группы:
- spatial topology, per-edge pitches, high-valence profile junctions и preview;
- eave miter / overhang / profile regressions;
- прежнее геометрическое ядро;
- headless Blender 5.2.3: регистрация, генерация плоских и пространственных крыш, создание профилей и фальцев, запись .blend, повторное открытие вторым процессом и Create/Update для сохранённых объектов.

Экспериментальный weighted-wavefront probe запускается отдельно с continue-on-error. Это диагностический путь, а не основание ослаблять валидацию основной генерации.
